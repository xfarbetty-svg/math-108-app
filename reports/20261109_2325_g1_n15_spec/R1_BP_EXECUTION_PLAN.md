## 1. 任務拆解卡

### T-01 幾何畫布與基準線
- **目標**：建立可視化底座與不可動搖的左端基準，確保「碰壁比較」的算理前提成立。
- **範圍**：
  - Web Component 骨架 `<snap-caliper-wall>`（Shadow DOM / 封裝樣式）。
  - SVG 視口 `360 × 220`（`viewBox="0 0 360 220"`），背景/刻度層與互動層分離。
  - 碰壁基準線：`x=30` 垂直鮮紅粗線（`#EF4444`, `stroke-width=3`），上端標註「基準線」文字。
  - 被測物渲染槽（鉛筆/蠟筆形狀或等價矩形表示），預設至少支援 A(180)/B(135)/C(90) 三組長度。
- **輸入/依賴**：R0 幾何參數（§2 視覺幾何參數）。
- **產出**：
  - `render()`/初始 SVG 結構；基準線為常駐元素（不隨被測物移動）。
  - `setObject({ name, length })` 能在未對齊狀態下放置物件（初始左端可為 `X=80` 等非對齊位置）。
- **完成定義 (DoD)**：視口尺寸正確、基準線位置/色/寬度/標註符合規格；被測物可被設定並顯示。
- **風險/備註**：文字標註與 SVG 字型佔用位元組，需納入 D-01 體積預算管控。

### T-02 磁吸靠齊狀態機
- **目標**：消除「左端懸空誤判」，以狀態機強制建立合法比較起點。
- **範圍**：
  - 狀態流：`IDLE → WALL_ALIGNED`（可由拖曳近牆或 `alignWall()` 觸發），並支援 `READOUT/WALL_ALIGNED → WALL_ALIGNED`（切換物件/重設單位後回到已對齊）。
  - 磁吸規則：當 `|objectX - 30| <= 15`（拖曳釋放/靠近判定）或呼叫 `alignWall()`，物件左端平滑吸附至 `X=30`。
  - 事件：吸附成功派發 `CustomEvent('caliper-event', { detail: { type: 'align', status: 'WALL_ALIGNED', ... } })`；同時支援 `align:snapped` 語意（可作為 detail.status 或相容事件，依實作統一文件化）。
  - `getState()` 反映 `aligned` 與當前 `status`。
- **輸入/依賴**：T-01 畫布與物件座標模型。
- **產出**：`alignWall()` 公開方法；內部 `snapToWall()`；拖曳/點選對齊互動（若採點選優先以節省體積，需保留 API 行為一致）。
- **完成定義 (DoD)**：AC-07-1 通過；未對齊時不得進入有效量測讀數（READOUT 需在 WALL_ALIGNED 前提下）。
- **風險/備註**：拖曳實作（pointer events）較佔體積；若超預算，改為「靠齊基準線」按鈕 + 近牆自動吸附判定的最小實作，仍須滿足 AC-07-1 When 條件的可驗證行為。

### T-03 個別單位鏈鎖定
- **目標**：以「頭尾相扣成鏈」杜絕空隙與重疊，落實個別單位量測算理。
- **範圍**：
  - 單位常數：迴紋針 `UNIT_LEN=45px`, `UNIT_H=18px`；首枚左端 `X=30`，第 `k` 枚左端 `30 + (k-1)*45`（1-based）。
  - 操作：`addUnit()`、`removeUnit()`、`autoMeasure()`（依 `objectLength` 填滿至 `ceil(length/45)` 或規格定義的恰好覆蓋策略；需與 READOUT 一致）。
  - 幾何無縫性：渲染時相鄰迴紋針邊界共用同一 x 座標，禁止額外 gap/margin；重疊檢測以座標公式保證（非僅視覺）。
  - 狀態：`WALL_ALIGNED → CHAIN_SNAP`（加入/調整單位鏈時）；`getState()` 回傳 `unitCount`, `measuredLength (= unitCount*45)`, `objectLength`。
  - 事件：`type: 'snap'`（detail 含 `unitCount`, `status`）。
- **輸入/依賴**：T-02 已對齊前提；T-01 渲染層。
- **產出**：單位鏈資料結構（僅計數即可，避免陣列冗餘）；SVG 迴紋針符號（可用 `<g>`/`<rect>`+圓角簡化以省體積）。
- **完成定義 (DoD)**：AC-07-2 通過；任意 `k>=1` 位置公式成立；`removeUnit()` 下限為 0 且狀態一致。
- **風險/備註**：迴紋針造型細節易膨脹體積，採幾何等價簡化（保留「可辨識為單位」與 45px 長度語意）。

### T-04 讀數徽章與比較模式
- **目標**：將量測結果轉為可讀的數學語句，並支援兩物體同基準直接比較。
- **範圍**：
  - 讀數（READOUT）：當 `measuredLength === objectLength`（或依 AC-07-3「剛好等於/接近」採精確匹配策略；本案以 45px 整數倍對齊物件長度，採**精確匹配**）→ 狀態 `READOUT`/`READOUT_EXACT`，顯示右端垂直對齊輔助虛線與徽章「剛好 N 根迴紋針長」。
  - 直接對比：`compareMode()` 讓兩筆在同一起跑線 `X=30` 並排（上下分列），超出長度以金色框標示，標註「長出 M 根迴紋針」（M 依 45px 單位差計算）。
  - 狀態回復：`READOUT → WALL_ALIGNED`（切換被測物或重設單位）。
  - 事件：`type: 'readout'`（detail 含 `status`, `unitCount`）。
  - `reset()` / `getState()` 完整性。
- **輸入/依賴**：T-01~T-03；AC-07-4 需雙物件資料模型（可由 `setObject` 擴充或 compare 專用參數，實作時以不破壞既有 API 為原則並文件化）。
- **完成定義 (DoD)**：AC-07-3、AC-07-4 通過；徽章/虛線/金框可見且文案正確。
- **風險/備註**：雙物件並排與文案佈局需避免超出 360×220 視口；比較模式的 API 形狀（是否傳入第二物件）需在實作前定案並反映於驗收頁。

## 3. 偏離與邊界裁決

### D-01 獨立體積預算 ≤ 12,288 B
- **裁決**：`app/components/snap-caliper-wall.js` **單檔 UTF-8 位元組數 ≤ 12,288 B**（以 `fs.statSync`/`wc -c` 等位元組計量，非字元數）。超標即 **FAIL**，不得以「壓縮後」或「gzip」計。
- **執行策略**：
  - 禁止外部依賴（CDN/CSS/JS/import 第三方）；僅原生 Custom Elements + SVG + 內嵌樣式字串。
  - 造型簡化：迴紋針用最小 SVG 幾何（矩形/圓角）表達；避免冗長 path。
  - 程式風格：短識別名（發佈前）、合併重複字串、避免大型模板註解；不犧牲 AC 正確性。
  - 拖曳若導致超標，降級為「靠齊基準線」按鈕 + 閾值吸附（仍滿足 AC-07-1 可驗證行為），並在驗收頁註記。
- **量測點**：實作完成後、`node --check` 後、驗收頁執行前各量測一次；CI/驗收清單記錄實際位元組。

### D-02 迴紋針卡扣幾何無縫性
- **裁決**：以**數學座標**定義無縫，視覺為輔。
  - 第 `k` 枚（1-based）左端 `x_k = 30 + (k-1)*45`，寬 `45`，右端 `x_k + 45`。
  - 無縫條件：`x_{k+1} - (x_k + 45) === 0`（px，SVG user space）。**禁止** `margin/gap/translate` 額外偏移。
  - 無重疊條件：任意相鄰不出現 `x_{k+1} < x_k + 45`。
  - 首枚錨定：`x_1 === 30`（基準線）恒成立（CHAIN_SNAP 階段）。
- **驗收取證**：驗收頁直接讀取每枚元素的 `x`/`transform` 計算後座標，或由元件暴露 `getUnitPositions()`（若為測試友善 API，需控制體積）/ 透過 `getState()`+公式驗證。
- **邊界**：`unitCount=0` 合法；`removeUnit()` 不使剩餘鏈位移。

### D-03 兩筆直接比較之對齊約束
- **裁決**：比較模式下**兩筆左端必須同為 `X=30`**（同一起跑線 = 基準線），上下並排僅改變 y，不改變 x 起點。此為算理硬約束，優先於美觀。
- **差值計算**：以 45px 個別單位呈現「長出 M 根迴紋針」，`M = (maxLen - minLen) / 45`；若長度非 45 倍數（擴充情境），以四捨五入/規格另訂為準，本案 R0 給定長度皆為 45 倍數，驗收採整數斷言。
- **互動約束**：比較模式中禁止單獨拖動任一筆脫離 `X=30`（或拖動後自動回吸至 30）；若允許切換比較對象，切換後仍須滿足 D-03。
- **API 定案建議**：`compareMode(objectA, objectB)` 或 `bench.setComparePair(...) + bench.compareMode()`；驗收頁以實際公開介面為準，並補測 `getState()` 在比較態的可解釋性。

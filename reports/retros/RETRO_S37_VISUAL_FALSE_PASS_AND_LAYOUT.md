## 🚨 三大核心事故剖析與血淋淋真相

### 1. 事故一：48:52 橫屏劇院規格硬套 390px 手機直屏，導致排版徹底崩塌
- **根因追溯**：`036_local_painter` 原先設計的 48:52（左側角色、右側演武場）是在 16:9 電視螢幕或 1024×1024 桌面環境下的劇院比例。
- **直屏災難**：在 390px 手機直屏下硬切左右雙欄，左側僅剩 187px、右側僅剩 202px。
  - 12 格長條巧克力在 202px 內被擠成一條不到 15px 寬的細線，無法操作。
  - 垂直方向被拉長至 600px+，右側中間產生了近 400px 的「死黑巨大虛空」。
  - 米米全身角色被粗暴裁切成正方形大頭貼，毫無課堂環境與光影質感。
- **結論**：手機直屏（Portrait 390px）**嚴禁硬套左右 48:52**，必須轉為「上方 16:9 劇院小講堂 + 下方全寬 390px 飽滿操作演武場」之上下架構！

### 2. 事故二：AGY 越權手刻任務卡，工兵把內部 Debug 標籤直接砸在孩子臉上
- **違規事實**：AGY 在接收到使用者「條與塊」的教學法指導後，未依規約調度 035 通道三產出嚴密 Task Card，而是自行動筆寫出粗糙任務卡。
- **工程外溢**：工兵機械化理解全域防錯規則中的「降級必有痕跡」，竟在兒童教學對話框頂端生生插入紅底白字的 `語音降級：改以字幕節奏推進`，底欄掛上 `● 配音：語音略過（瀏覽器限制）`。
- **教訓**：兒童教學 UI 嚴禁出現任何內部工程日誌與 debug 提示！若音訊自動播放受限，必須純前端靜默優雅推進，絕不可騷擾學生。

### 3. 事故三：035 多模態視覺盲審發生「假辨識 / 假放行」（偽真理重大破綻）
- **抓包真相**：`verify_visual_qa.py` 在調用 035（`gemini-2.5-flash` @ `127.0.0.1:4000`）審查 390px 兔子截圖時，代理轉發 base64 發生錯位或上下文混淆。模型回報中竟然宣稱看到的是「歷史記錄列表、白色卡片、Base64 文本、底部四個導航圖標」，並盲目回傳了 `pass: true`（Exit Code 0）！
- **虛假賦能**：AGY 單憑 Exit Code 0 假象，未肉眼覆核報告內容，差點將這份四不像半成品推向收工交付！
- **軍規升級**：035 多模態視覺審查報告**必須雙重校驗 `detected_elements` 與預期場景的語意匹配度**，若辨識出的物體與畫面不符，一律視為假成功并直接熔斷！

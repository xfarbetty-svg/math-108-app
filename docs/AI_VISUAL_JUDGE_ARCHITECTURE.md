## 零、事故痛點與深刻反思（不推諉、不甩鍋）

在過去的題目開發中，系統暴露出三大深層病灶：
1. **大腦假覆核（Fake Review）與責任推諉**：
   - 工兵在代碼中將百位板偷工減料畫成 2x2 的「綠色田字」、用 2 條充當 10 條，大腦僅憑命令列回傳 `Exit Code 0` 即盲目簽核放行。
   - 面對使用者質疑時，大腦竟下意識推託「工兵挑軟柿子吃」，嚴重違背「實事求是契約」。
   - **法定責任定錨**：工兵只負責執行指令，**檢核與覆核的法定責任 100% 在大腦身上**！
2. **條件寫不完的死胡同（頭痛醫頭）**：
   - 若每換一題（百位板、十朵花、五隻青蛙）就手寫一條代碼硬斷言，系統必被無限條件淹死。
   - 必須依靠**「通用資料驅動組件」**與**「AI 自然語言視覺斷言」**之通則來化解。
3. **調研浮於表面，未深入核心**：
   - 過去雖調研了 GitHub 專案，卻只學到「裝相機截圖」，把最關鍵的「法官裁決機制（Judge）」與「語意斷言」丟在一旁。

## 二、解答疑義：什麼是「獨立法官」？它是雲端的 CDP 嗎？

### 1. 什麼是 CDP？
- **CDP (Chrome DevTools Protocol)** 是 **本機 Chrome 瀏覽器的底層控制協議**（完全在本機，非雲端）。
- 它的角色就像是「無人相機與機器人手指」：負責在本機無頭瀏覽器中打開網頁、點擊選項、截取高解析度螢幕截圖。

### 2. 什麼是「獨立法官（Judge）」？
- **法官不是 CDP，法官是「拿著相片嚴格打分數的考官」**。
- 它是由本機或平價多模態模型（如 Gemini Flash / 地端視覺模型）擔任的一個獨立檢核進程。
- **為什麼稱作「獨立」？**
  - **工兵思維**：「我代碼寫完了，看起來有綠色方塊，我給自己滿分。」（容易自欺欺人）
  - **法官思維**：不參與代碼編寫，只拿到「真題考卷截圖」與「CDP 拍下來的實機截圖」，帶著懷疑視角去挑刺。
  - 法官只輸出結構化結果：
    ```json
    {
      "success": false,
      "failure_reason": "百位板僅畫出 4 格田字，缺少 10x10 共 100 格的數學幾何細節，不符合小學二年級算理！",
      "gotchas": ["嚴禁使用田字方塊代替百格板"]
    }
    ```
  - 一旦 `success === false`，系統自動觸發熔斷，工兵必須重寫，根本不會打擾使用者！

## 三、通則化防線：從根本消滅「寫不完的條件」

為避免陷入「十條十格條要寫一條、十朵花要寫一條、十隻青蛙又要寫一條」的無限補丁地獄，確立三大通則：

```mermaid
flowchart TD
    subgraph 輸入端
        Q[段考真題 JSON 資料]
    end

    subgraph 通則一：資料驅動通用組件
        Q -->|傳入數量與類型| Comp[通用教具容器\nPlaceValueBoard / ItemCounter]
        Comp -->|自動循環渲染| Dom[保證真實數量與細節的 DOM/SVG]
    end

    subgraph 通則二：本機 CDP 拍照取證
        Dom -->|本地無頭 Chrome| CDP[原生 CDP 1秒高解析截圖]
    end

    subgraph 通則三：AI 獨立法官裁決
        CDP -->|實機圖 ＋ 考卷原圖| Judge[獨立法官 Judge]
        Judge -->|Midscene 自然語言斷言| Assert{語意是否全過？}
        Assert -- 未細分田字 / 數量不對 --> Fail[退回工兵重寫\nExit 1 熔斷]
        Fail --> Comp
        Assert -- 100% 吻合真實算理 --> Pass[產出 Lost-Pixel 雙圖對照卡片\n呈報人類 3 秒完工核准]
    end
```

### 1. 通則一：通用教具容器庫（封死工兵塗鴉空間）
- 嚴禁工兵在各題目 HTML 中臨場手繪 `div` 方塊。
- 建立全域通用 Web Components：
  - `<place-value-board hundreds="2" tens="7" ones="8">`：百格板組件內部自帶 10×10 網格演算法，十格條自帶 10 節，個位自帶 1×1。
  - `<item-counter type="flower" count="10">`：傳入 `flower` 與 `10`，自動渲染 10 朵花。
- **效益**：工兵只能傳入題幹數字，再也無法畫出田字！

### 2. 通則二：Midscene 自然語言斷言通則
法官審查時，不寫死特定的 CSS 類名，統一執行三大自然語言斷言：
1. **【教具真實性】**：「畫面中呈現的數學具象物，必須結構完整且具備真實細節，嚴禁使用未細分的簡化色塊或田字格充數。」
2. **【數量一致性】**：「題幹中要求的具體數量（如 N 朵花、N 隻青蛙、N 條積木），畫面中繪製的物件個數必須能直觀數出且與數字完全一致。」
3. **【版面健康度】**：「單屏完全容納，無文字重疊、截斷或遮擋。」

### 3. 通則三：題幹 Jaccard 相似度演算法（防雙胞胎水題）
- 題庫驗收自動比對同單元題幹文字相似度。
- 若兩題文字重合度 $> 65\%$（如「150是幾個十」與「120是幾個十」），自動判定為灌水水題，直接退件，徹底消滅無效湊題。

## 四、驗收與責任交付約定

1. **大腦先背書**：交付報告必須包含法官判決書與雙圖對照卡片。
2. **人類只做最終「3 秒確認」**：把所有除錯、數積木、抓田字的疲憊留在後台，人類只需看最終漂亮的對照卡片，確認順眼即可。
